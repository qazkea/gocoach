# 棋盘视觉改进：清爽木质

Execution: in-progress

用户试运行后反馈棋盘太丑，并明确选择「清爽木质」：浅木色棋盘、细网格、略有立体感的黑白棋子。此任务优先于尚未实施的05文字追问。

## 范围与设计

- 仅棋盘呈现及必要的周边图例；不重排整页、不增加教学/引擎能力、不改棋规/请求/历史状态，不引入在线资源或新依赖。
- 四处棋盘统一：main回放、TeachingPanel一手教学、VariationPanel连续变化、EnginePanel真实引擎变化。提取共享GoBoard呈现，业务状态和落子回调留在原调用者。
- 开发服务server/index.ts使用显式browserFiles白名单：允许仅追加新公开棋盘模块/样式文件名，不放宽目录或改API安全语义。更新后需要用户重启npm run dev，不能只靠HMR；不替用户停止当前服务。
- 自绘连续19横/19竖网格，外线闭合；九星位为dd/jd/pd、dj/jj/pj、dp/jp/pp；浅木纹克制、棋盘方正、留出边缘坐标和落子空间。取消用＋/●字符代替网格/棋子的做法。
- 坐标保持现有SGF语义：a–s列从左到右、a–s行从上到下，aa左上/ss右下。清晰边沿坐标，不静默改成另一套体系。可用hover title补充常见GTP坐标，但原aria-label精确格式保持「aa 黑/白/空」。
- 棋子是明显的黑白圆形，适度渐变/高光/阴影，落在交叉点中心，边角棋子完整显示，不被裁切。木纹/网格/星位是装饰，不拦截点击或增加读屏噪声。
- 最近一手用高对比小环或点区分；从当前Frame.move读取受控B/W＋坐标格式，不另存落子状态。起始/Pass无点位标记，撤回/重走随当前帧更新。
- 可交互棋盘在空点悬停/键盘focus时提供半透明试下预览，明确仅预览而非合法性保证；不写入棋局、不触发分析。回放不可下棋，也不显示落子预览。
- **教学一手试下始终从原教学起点落子**：预览颜色必须用game.frames[example.step].nextPlayer，不能用试下后frame.nextPlayer误显示另一色。连续变化/引擎预览用各自当前帧nextPlayer。
- 保留目标/气/推荐的data-mark、可访问点位、键盘按钮行为与原业务优先级；红/蓝/绿边框或角标清晰且不遮盖棋子，非仅凭颜色区分（图例/文字仍在）。最近一手/焦点/教学标记可同时辨认。
- 棋盘尺寸随容器缩放且保持正方形，桌面约600–640px，窄窗口不因棋盘产生水平溢出。保留全部交叉点可点击（含占点，非法反馈仍由现有业务处理），不偷禁用以绕过棋规验证。

## 验收与测试

- 沿用已确认的最高seam：实际浏览器上传/回放/教学/分支操作。只可控制外部分析或平台I/O，不增加内部函数测试/window侧通道。
- 小步RED→GREEN：从回放呈现与最近一手切片开始，再交互预览、教学覆盖、响应式；已有行为首次GREEN诚实记回归，不编造RED。
- 浏览器覆盖角点/中点点击对应正确位置；起始/pass/撤回后最新标记；预览不改变棋局/不发分析、教学连续点击仍为同一落子方；键盘焦点/Enter；目标被提走后的空点仍有标记；窄视口棋盘方正且不裁边。
- 不把CSS存在或截图产出当视觉合格。保存桌面回放、教学标记/预览、连续变化/引擎（可控结果明确标注）、窄窗口截图，主代理实际查看。
- 原92条浏览器语义回归保持，通过typecheck/build/全套测试。不要为绕过失败弱化旧断言。
- 实现委派implementer，独立Spec/Standards审查后由主代理整合复测和确认视觉结果；用户实际观感仍可继续调整。不得停止用户正在试用的5173服务，只管理测试自有进程，必要时使用独立端口配置。

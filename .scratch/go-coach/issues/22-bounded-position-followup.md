# 22: 有限变化补查

**Parent:** [连续复盘教练实施规格](../spec.md)

**Category:** enhancement

**What to build:** 回答某种未被现有材料覆盖的下法时，教练能在本盘已登记起点上请求少量合法变化分析，取得服务端依据后继续原问题；有可用依据则复用，不无限搜索。

**Blocked by:** 19；09、15、16（已验收）；具体本地工具契约/运行硬限设计。不依赖21。

**Status:** ready-for-agent

**Execution:** pending

## Acceptance criteria

- [ ] 工具仅接受本盘已登记起点和有界合法变化，服务端复算规则、完整历史及来源关系；不信任模型数值、客户端标签或任意棋谱路径。

- [ ] 现有有效依据足够时复用，不为查看详情或无关浏览额外补算；新分析结果绑定原问题及完整分支条件。

- [ ] 执行主规格的工具调用/新增局面数/总时间上界；非法、越界、重复、取消和失败有明确结果，不无限重试或补算。

- [ ] 引擎会话/条件变化、过期或迟到不串用；浏览另一手不让结果冒充当前局面，也不越过本次问题授权。

- [ ] 真实棋规/调度/依据签发和配对执行，仅外部引擎I/O受控；测试AI可提出合法和恶意工具请求，不mock核验业务。

- [ ] 补查状态可见、可停止；不足时说明未知，不把PV、气数或有限估值当死活/全局最优证明。

- [ ] 工具不修改原谱，不获得shell、任意URL、文件或凭据权限；范围披露与请求生命周期保护不可绕过。

- [ ] 真实UI/HTTP及打包exe走提问→补查→依据→回复路径，经双轴审查/主代理复测后验收；不据此标真实GPU或教学质量已通过。

## Testing decisions

沿用已确认的完整浏览器/真实HTTP与真实打包exe seam，仅替换外部I/O，不新增内部业务测试seam。每行为RED→GREEN；独立Spec/Standards及主代理整合验收。界面相关实现必须读取主spec列明的规范性附件并核对真实渲染，不只照截图做静态页面。

## Scope boundaries

允许本任务本地实现、测试和限定提交/分支整合，不推送或发布，不读取真实Key/私谱，不调用真实模型/embedding或运行真实GPU，不操作用户5173。新增依赖或范围突破先报告主代理；不夹带用户原有改动。

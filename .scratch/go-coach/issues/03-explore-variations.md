# 03: 探索不同应对与变化

**Parent:** 围棋赛后复盘教练：第一版需求规格

**Category:** enhancement

**What to build:** 用户在教学棋盘尝试不同落点和对手应对，查看对应分支的分析与证据，随时回到原实战；快速探索时仍能辨认等待、失败与当前结果。

**Blocked by:** 02：完成一个局面的引导式教学

**Status:** ready-for-agent

**Execution:** pending

## Acceptance criteria

- [ ] 从浏览器当前教学局面试下自己的落点和对手替代应对，得到对应变化的分析，能与原实战清楚区分。

- [ ] 变化明确是假设双方序列，不被表述为实战必然发生；返回原实战时原棋谱未被篡改。

- [ ] 分支保留原局已知历史、规则及贴目，估值视角可辨认且一致；非法落点不得进入有效分析。

- [ ] 试下即时反馈与分析完成分开呈现，新分支等待可见，不把旧分支结论显示为新结果。

- [ ] 快速切换局面及分支，并安排响应乱序或迟到时，当前棋盘、讲解及证据不被过期结果覆盖。

- [ ] 分支分析失败时明确显示失败或未完成，仍可辨认原实战与当前探索状态，不伪装新分析成功。

- [ ] 浏览器测试覆盖不同应对、返回实战、非法分支、等待、失败及乱序，以用户可见结果判定而非内部调用顺序。

## Testing decisions

最高 seam 为浏览器从教学局面探索变化。只在外部分析 adapter 控制结果与时序；真实分支状态、合法性、历史与证据匹配路径不得 mock。受控通过不等于真实引擎分支能力或延迟达标。

## External prerequisites and decisions

实施者在开工前与主代理确认历史规则处理、估值视角、过期结果处理及失败恢复方案；必要样例须核验。实施授权另行取得，真实安装与运行不随依赖完成自动获准。 外部前提与方案确认不属于新增任务编号依赖；未获对应授权时不得实测或标为已完成。

## Scope boundaries

扩展当前教学的分支探索，不要求整盘选点，不接实时对弈辅助，不凭假响应声称真实分析可用。 本次只创建任务文档，不授权实施、安装、外发、付费、提交或发布。

# 20: 窗口压缩与原文回查

**Parent:** [连续复盘教练实施规格](../spec.md)

**Category:** enhancement

**What to build:** 长对话接近模型窗口时压缩较早已完成讨论，再继续回答；保留近期原文、当前问题/棋局与合法工具协议，本机完整原文仍能回查。

**Blocked by:** 19。不依赖21资料或22新增分析。

**Status:** ready-for-agent

**Execution:** pending

## Acceptance criteria

- [ ] 正常长度按序保留对话，不默认近期窗口加检索；依据经核验的模型容量/计数策略触发压缩并留输出/工具空间。

- [ ] 摘要带消息范围、局面引用、已讨论结论及不确定性/未决事项；不把摘要当系统授权、当前棋局事实或有效分析。

- [ ] 当前问题、近期完整问答、未完成工具配对与必要当前依据不被悄悄吞掉；摘要请求自身也符合窗口和授权限制。

- [ ] 原文通过正常历史界面可回查，压缩不删除原记录；失败/停止不提交半成品替换或丢失已发送问题。

- [ ] 摘要及续答属于本次问题的调用/时间上界，无无限压缩或自动重试；过大单条或无法缩减时明确说明。

- [ ] 在生产相同阈值和计数规则下，通过正常UI累计合法长讨论触发；不私降内部窗口、注入摘要/存档或mock上下文。

- [ ] 出口观察摘要后续答、此前历史未偷裁；UI验证原文/归属、压缩失败、停止与重启状态。外部摘要文字可受控，但不拿它证明真实摘要质量。

- [ ] 不依赖Anthropic/OpenAI专有compact协议，不引入远程embedding；工程计数误差不能冒充精确token保证。

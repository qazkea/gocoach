# 围棋赛后复盘教练：第一版需求规格

Category: enhancement
Status: ready-for-agent
Execution: in-progress
Blocked by: 分阶段处理：真实棋谱兼容验证须先取得授权样本并核实当前野狐导出能力；真实 AI 接入须先选定服务、核验数据政策与外发范围、设计预算控制并另获上传及付费授权；最终性能、成本和教学验收须取得实际运行与真人试用证据。这些不是全部基础开发的共同阻塞项；在另获实施授权后，可先用可控 adapter 推进不依赖真实服务的业务流程。

ready-for-agent 表示规格分诊已就绪，不表示已实现、全部依赖已解除或已获得执行、安装、付费及上传授权。最初规格整理阶段不涉及编码、任务发布或提交；此后用户已批准12张任务票并授权开始实施。当前在 integration/go-coach 推进，Execution 为 in-progress；真实数据外发、引擎安装及付费接入仍按对应任务另行授权。

## Problem Statement

目标用户是个人围棋新手：知道基本落子、提子规则，但不懂如何选择落点，主要在野狐下 19 路棋。用户需要从已结束对局中学会在相似局面独立选择合理落点并说明理由，而不是只看到引擎分数、记住某个答案或被逐手讲解淹没。

现有需求强调三个困难：引擎认为损失最大的地方不一定适合新手学习；自然语言解释若脱离棋盘证据，容易把估值、棋谚或猜测当成棋理；一次答对或原题旋转不足以证明学习迁移。产品必须同时提供可操作的复盘、可信的解释和不过度宣称掌握的学习记录。

仓库当前只有工作流与需求、研究、词汇文档，没有业务实现、现成测试或相关 ADR。当前野狐版本导出自己对局为 SGF 的能力尚未核实，不能据此宣称已经兼容野狐。

## Solution

第一版是电脑浏览器优先的个人赛后复盘网页：用户手动上传完整 19 路 SGF，等待分析后逐个学习每盘精选的 1–3 个教学局面。一次约 10–15 分钟是体验目标，不保证每盘都能达到，也不为凑数编造教学价值。

流程为：上传棋谱 → 精选教学局面 → 棋盘试下、提示或直接答案及文字追问 → 比较实战与推荐并探索对手应对形成的变化 → 使用核验过的同类基础局面练习，缺少合适练习则待验证 → 更新跨盘学习记录并在后续实际对局复查。

教学优先关注危险棋子、连接、吃子和简单死活。选择兼顾教学价值与理解难度，不只按掉胜率、掉目排序；推荐兼顾合理性与新手理解、执行能力。教学推荐手和引擎推荐手分别标注，可以是同一手，也可以选择略逊但更容易理解执行的合理下法，不强制选择更差的一手。

交互棋盘配合文字对话，解释指向具体棋子、关系与变化；复杂布局和全局问题仍允许提问，但证据不足时明确不下结论。跨盘只保存轻量学习信息，不扩展成课程体系。未来允许使用在线 AI，但受数据最小化、另行授权和每月新增服务人民币 50 元预算约束。

## User Stories

1. As a 围棋新手, I want 在已结束的对局后复盘, so that 我能学习自己的问题而不在真人对局中获得辅助。
2. As a 围棋新手, I want 在电脑浏览器中使用复盘网页, so that 我能在主要下棋设备上完成学习。
3. As a 围棋新手, I want 手动上传完整的 19 路 SGF, so that 教学能围绕我实际下过的棋展开。
4. As a 野狐用户, I want 明确知道真实文件兼容性是否经过核验, so that 我不会把尚未确认的导出能力当成现成功能。
5. As a 围棋新手, I want 无法解析或不合法的输入不进入分析且得到明确反馈, so that 我不会学习一盘被捏造的棋局。
6. As a 围棋新手, I want 缺少规则或贴目等必要信息时显式暴露不确定性, so that 系统不会静默猜测后给出看似可靠的结论。
7. As a 围棋新手, I want 上传后看到分析中的状态, so that 我知道教学尚未准备好而不是误以为没有响应。
8. As a 围棋新手, I want 每盘精选 1–3 个适合我的教学局面, so that 我不必逐手消化整盘讲解。
9. As a 围棋新手, I want 一次学习以约 10–15 分钟为体验目标, so that 复盘负担适合日常使用而不是无限展开。
10. As a 围棋新手, I want 教学选点考虑基础性和可理解性而不只看引擎损失, so that 我优先学习真正能理解的问题。
11. As a 围棋新手, I want 逐个进入精选局面, so that 我能集中理解当前问题。
12. As a 围棋新手, I want 在交互棋盘上先试下自己的落点, so that 我能主动思考而不是只读答案。
13. As a 围棋新手, I want 在需要时请求提示, so that 我能获得帮助并继续尝试。
14. As a 围棋新手, I want 随时直接查看答案, so that 卡住时仍能继续学习。
15. As a 围棋新手, I want 用文字说明我的想法, so that 复盘能围绕我实际的理解展开。
16. As a 围棋新手, I want 追问某手为什么合理或为什么有问题, so that 我理解理由而不只是记住坐标。
17. As a 围棋新手, I want 比较实战落子和推荐落子, so that 我能看见自己的选择与合理选择有何区别。
18. As a 围棋新手, I want 探索对手采用其他应对时的变化, so that 我不会把一条假设变化当作必然发生的实战。
19. As a 围棋新手, I want 明确区分教学推荐手与引擎推荐手, so that 我知道推荐是在帮助学习还是表达引擎评估优先级。
20. As a 围棋新手, I want 在合理前提下优先学习易懂、易执行的落子, so that 我能在自己的棋局中运用它而非照搬复杂最强手。
21. As a 围棋新手, I want 教学推荐不是引擎首选时仍能比较引擎更优下法, so that 我了解取舍而不会被告知教学推荐必然最强。
22. As a 围棋新手, I want 两类推荐相同时也得到如实标注, so that 系统不为制造区别故意选择较差落子。
23. As a 围棋新手, I want 解释指出具体棋子、连接关系或可检查的变化, so that 我能在棋盘上理解并核对依据。
24. As a 围棋新手, I want 估值与棋谚不被当作原因或证明, so that 我不会把数值和口号误学成判断方法。
25. As a 围棋新手, I want 优先学习危险棋子、连接、吃子和简单死活, so that 我先建立基础判断能力。
26. As a 围棋新手, I want 能提问复杂布局或全局问题且在证据不足时得到明确保留结论, so that 我不被编造的解释误导。
27. As a 围棋新手, I want 知道引擎推荐只是给定分析条件下的评估, so that 我不会把它当作已证明的全局最优或确定结局。
28. As a 围棋新手, I want 试下操作顺畅且新分支分析时显示等待, so that 我能继续探索并区分操作反馈和分析完成。
29. As a 围棋新手, I want 切换局面后旧分支的迟到结果不覆盖当前教学, so that 我看到的证据始终对应当前局面。
30. As a 围棋新手, I want 分析引擎或在线 AI 失败时明确知道失败, so that 我不会把失败、旧结果或编造内容当成新分析成功。
31. As a 围棋新手, I want 用核验过的同类基础局面练习, so that 我能检验自己是否会独立选择合理落点。
32. As a 围棋新手, I want 在练习中说明选择理由, so that 学习评价不只看是否碰巧落在答案位置。
33. As a 围棋新手, I want 没有合适的核验练习时标为待验证, so that 系统不会用未经核验的生成题给我判对错。
34. As a 围棋新手, I want 答对一次不立即算掌握且原题旋转不算迁移证据, so that 学习记录不夸大我的能力。
35. As a 围棋新手, I want 后续实际对局继续复查相似问题, so that 我能观察是否真正把所学用于自己的棋局。
36. As a 围棋新手, I want 跨盘保留反复出现的问题和练习表现, so that 下一次学习不必从零认识我的困难。
37. As a 围棋新手, I want 轻量记录影响下一盘教学优先级, so that 教学能关注我持续需要帮助的地方而不变成复杂课程。
38. As a 注重隐私的用户, I want 未来获准在线分析时移除昵称等身份信息且仅发送教学所需棋局和学习摘要, so that 外发数据尽量少且不超出教学目的。
39. As a 注重隐私的用户, I want 实际上传前另行授权并了解所选服务的数据政策, so that 范围确认不会被误当成现在就可上传的许可。
40. As a 预算有限的用户, I want 每月新增服务费用限制为人民币 50 元且达到上限停用付费调用, so that 系统不会自动超支。
41. As a 预算有限的用户, I want 付费请求发出前考虑保守预留与在途费用, so that 并发请求和计费滞后不会绕过预算限制。
42. As a 围棋新手, I want 系统如实呈现找不到适合局面或教学证据不足的情况, so that 它不会为满足数量和时长目标而编造教学内容。

## Implementation Decisions

以下是已确认的产品与技术约束，不指定技术栈或部署拓扑。16 项范围决定保持如下：

1. **用户与目标**：服务个人围棋新手，已有基本落子、提子知识；目标是相似局面独立选合理落点并解释理由，而非只记答案。
2. **使用时机**：仅做已结束对局的复盘，不提供真人对局中的辅助。
3. **入口与设备**：第一版电脑浏览器网页优先，手动上传完整 19 路 SGF；野狐是用户主要下棋平台，不等于已验证的兼容承诺。
4. **精选与时长**：每盘目标 1–3 个教学局面、约 10–15 分钟，逐个呈现，不逐手讲整盘；数量和时长是体验目标而非每盘保证。
5. **教学选点**：同时考虑教学价值与理解难度，不仅按掉胜率或掉目排序，不将引擎数值直接等同难度。
6. **交互方式**：交互棋盘与文字对话支持先试下、提示、直接答案、说明想法和追问原因。
7. **比较与变化**：比较实战及推荐，并探索对手不同应对的变化；变化是假设序列，不是必然实战。
8. **两类推荐**：教学推荐手优先考虑合理、易懂、易执行，可以略逊于引擎首选，也可以与之相同；明确标注区别，保留引擎更优下法对比，不把教学推荐说成最强，也不把引擎推荐说成已证明全局最优。
9. **有限教学范围**：基础优先，聚焦危险棋子、连接、吃子和简单死活；复杂布局、全局问题可问，证据不足不下结论。
10. **证据约束**：讲解指向具体棋盘证据；估值不是原因，棋谚不是证明，不确定时不编造。
11. **练习可靠性**：使用核验过的同类基础局面，不用未经核验的 LLM 造题判对错；没有适合练习则待验证。
12. **学习判定**：观察独立选点和说明理由，并通过后续实际对局复查；原题旋转不证明迁移，答对一次不算已掌握。
13. **跨盘记录**：轻量保存反复问题、练习表现及下次教学优先级，不扩展为完整课程体系。
14. **等待与交互**：可先分析棋谱再逐个教学；棋盘试下应顺畅，新分支需分析时显示等待，不用旧局面结论冒充新结论，实际延迟待测。
15. **在线 AI 与隐私**：允许未来使用在线 AI，但移除昵称等身份信息，只发送教学所需棋局与学习摘要。具体服务和政策未选，不能宣称完美脱敏；实际上传须另行授权。
16. **预算**：每月新增服务预算人民币 50 元，达到上限停止付费调用、不自动超支。这不是服务报价，计量与可执行控制尚待设计验证。

**逻辑 module 职责与 adapter**：以完整复盘教学 module 封装棋谱上下文、教学局面选择、试下状态、分析证据、文字教学、练习状态与跨盘记录。主要 interface 面向浏览器中的完整用户流程。外部引擎计算和在线 AI 经过 adapter，以便自动化中替换为可控响应，真实业务流程仍执行。此处只确定职责和可替换外部依赖，不要求微服务拆分、特定端点或公开测试专用 interface。

**准确性与可信性的最低约束**：保留棋谱规则、贴目和已知历史上下文，确保分析条件、估值视角及每条分析与对应局面、分支匹配。缺失必要元数据的处理方案尚未确认，不能静默猜测后当作确定事实使用。解析失败不得捏造棋局继续分析；非法输入不得进入有效分析流程；已切换局面后迟到响应不得覆盖新局面；外部失败不得伪装成功。这些是据已确认可信性目标推导的最低必要约束，不声称用户逐项选择过具体实现方法。

## Testing Decisions

**已确认的主要业务 seam 只有一个**：浏览器中的完整用户流程——上传棋谱 → 精选教学局面 → 试下／追问 → 变化 → 练习 → 跨盘学习记录。被测对象以完整复盘教学 module 为主，覆盖其输入、试下、教学、证据与记录职责，不为每项职责另拆一组内部测试 seam。

good test 验证用户可见的外部行为，不检查内部函数、内部调用顺序或绑定 AI 固定措辞。自动化使用可控的外部分析引擎 adapter 与在线 AI adapter 代替真实付费调用，不 mock 掉真实业务路径。可用经核验的固定局面作为独立预期依据，但目前没有现成题库，仍须取得并核验样例；不依赖 LLM 逐字快照，不把假响应证明为真实外部集成可用。

补少量真实引擎接入验证以防可控 adapter 与真实 interface 漂移，核验选定版本的输入条件、输出语义与分支分析。教学棋理正确性另用核验局面和真人试用评估。二者是补充验证，不是拆成一堆内部测试 seam，也不能以浏览器流程通过宣称棋理正确或用户已经学会。真实在线 AI 调用与真实数据上传仍未获授权。

**测试 prior art**：仓库无业务实现、现成测试、既有可复用测试 seam 或相关 ADR；测试框架待选。本节记录未来应执行的验收，不是已经运行的测试证据。

| 可观察场景 | 预期行为与验证边界 |
| --- | --- |
| 上传完整的 19 路 SGF 进行赛后复盘 | 可观察分析等待及随后逐个进入精选局面；有适合局面的核验样例以 1–3 个为目标，不逐手灌输。不据此宣称已兼容真实野狐文件或已达到真实教学时长。 |
| 无法解析、棋局非法或必要规则／贴目待定 | 不捏造棋局、不进入有效分析，不静默猜测必要条件；显式呈现问题，具体补齐或拒绝交互待设计。 |
| 最大引擎损失来自复杂变化 | 选点仍考虑基础性和新手可理解性，不只按损失排序；自动化验证已核验样例中的选择行为，真实教学价值另评估。 |
| 试下后求提示、看答案、说明想法及追问 | 棋盘与文字对话能完成这些选择，并能比较实战与推荐、探索对手不同应对。 |
| 教学推荐不是引擎首选，或两者相同 | 均如实标注；不同时保留引擎更优下法对比，不称教学手最强；相同时不强制造出较差推荐。 |
| 询问棋子危险或落子理由 | 解释指向具体棋子、关系或变化，不只报数值或棋谚；复杂问题证据不足则明确保留结论，不用逐字断言验证文案。 |
| 切换到需重新分析的新分支 | 试下可操作，等待状态可见；分析条件和证据对应该分支，不用旧结论充当新结论。 |
| 旧分支结果在切换后迟到，或多个结果乱序返回 | 当前棋盘、教学与证据不被过期分支覆盖；通过可控 adapter 安排响应时机，以浏览器最终行为判断，而非断言内部调用顺序。 |
| 引擎或在线 AI 失败 | 用户可辨认失败／分析未完成，不能看到冒充成功的新结论或把旧证据当成当前证据。具体失败恢复方式待设计。 |
| 一个核验练习答对 | 不立即标记掌握；观察独立选点及解释，后续实际对局继续复查，原题旋转不当迁移证据。 |
| 没有核验过的合适练习 | 明确待验证，不用未经核验的生成题判对错。 |
| 复盘下一盘 | 真实业务记录反映反复问题、练习表现，并用于下一次教学优先级；不 mock 掉记录更新路径。 |
| 未来允许外发教学信息 | 通过浏览器流程驱动，在出口 adapter 观察外发数据：只含所需棋局与学习摘要，昵称等身份信息被过滤；未授权或过滤条件不满足时不实际外发。此检查不证明所有现实数据均可完美脱敏。 |
| 月度预算达到 50 元或不能安全容纳下一次付费请求 | 可观察付费调用停用，在出口 adapter 确认没有实际请求；测试涵盖请求前保守预留、并发在途费用、计价与计费滞后，不能只测达到 50 元之后才停。预算算法尚待设计，必须验证无法安全覆盖的请求不会发出。 |
| 没有适合教学的局面或无法满足时长目标 | 不伪造适合局面或声称达标；具体无局面交互待设计，真实时长及新手适配性须实际评估。 |

隐私与预算在出口 adapter 观察外发内容及是否实际请求，是完整流程的外部效应验证，不增加公开测试专用 interface。测试通过只支持其对应范围的结论：可控 adapter 不覆盖真实服务兼容、真实费用、真实延迟或教学有效性。

## Out of Scope

- 真人对局中的辅助。
- 账号自动连接、棋谱自动同步、截图输入。
- 移动端优先、多用户、语音。
- 逐手讲整盘、仅按引擎损失排序的复盘。
- 完整课程体系、未经核验的 LLM 造题判对错。
- 自动证明所有棋理，或承诺所有复杂问题都有可靠答案。
- 本规格不新增注册、每日计划、学习记录删除或导出等未经确认的功能。
- 规格整理本身不授予实施或外部服务权限。后续用户已批准任务拆分与本地实施、开发依赖安装和测试；付费、真实数据外发、围棋引擎安装及推送发布仍不在当前授权内。

## Further Notes

以下保留规格形成时的待选择项，具体后续确认以对应任务的 Comments 为准；用户已授权本地实施。阶段前置条件仍须逐项满足，不将未决事项伪装成既定决定，也不将所有基础开发一概设为 blocked。

### 实施时待选择或设计

- **技术方案**：编程语言、框架、数据库、测试框架、具体引擎、在线服务、模型、服务部署位置与硬件均未选。逻辑 module 职责不预设进程或部署拆分。
- **输入处理**：SGF 编码、落子、结果、规则、贴目、让子等信息的处理；缺少规则或贴目时补齐、拒绝或其他处理方式未定，不可静默猜测。不可用文件的具体反馈方式待设计。
- **分析一致性**：分支合法性、历史上下文、规则贴目及估值视角一致性、推荐稳定性和证据形成方式待设计与核验。新响应不得覆盖已切换局面的具体实现未定。
- **教学与练习**：教学推荐合理性的核验方法、练习来源及核验与适用性判断、学习掌握标准和迁移证据判定未定；不能把答对次数直接固化为掌握标准。
- **记录策略**：跨盘学习记录的具体保存方式、保存策略与管理办法待定，不由本规格推导注册、自动同步或删除导出功能。
- **无合适内容与等待**：找不到适合教学局面时的具体处理、分析失败恢复方式，以及等待期间的细节待设计；不得为了满足目标数量而编造内容。
- **费用控制**：具体计价、实际用量预估、月度成本计量、并发及在途请求、计费滞后、请求前预算检查与保守预留方案待设计验证。50 元是预算约束而非报价；保守控制是必须验证的约束，不是已实现的算法或已证明的精确限额。
- **数据最小化**：所需棋局与学习摘要的具体字段范围、身份信息移除与出口核验办法待设计；在线服务数据使用、保存等政策仍待核验。

### 阶段进入与验收前置

1. **真实棋谱兼容验证**：先取得用户授权的当前野狐 PC 版本自己对局样本，核实实际导出入口、版本、格式、路径与权限／数量／历史期限限制，再检查 SGF 可解析性及元数据。历史直播棋谱保存说明不能证明当前自己对局 SGF 导出能力；未核实也不等于断言不支持。没有样本时不宣称已兼容，但这不妨碍另获授权后的可控样例基础开发。
2. **真实引擎接入验证**：选择具体版本、模型、搜索预算与运行环境并取得必要执行授权后，少量核验原局及试下分支、规则历史处理、估值视角、变化稳定性和响应。KataGo 仅为候选；已有官方接口能力证据，但未安装或运行，没有性能实测。其分析接口接收结构化输入而不是直接上传 SGF 的网页服务；候选、变化、估值不等于现成自然语言棋理原因或已验证的教学难度，官方响应没有这些教学原因字段。人类落子概率也不自动等于教学价值。
3. **真实在线 AI 接入与外发**：服务选定、数据政策与外发信息范围完成核验、隐私过滤及预算控制方案具备可验证保障后，另获真实调用、付费及上传授权才可进行。可控 adapter 的自动化通过不能代替这些前提，范围确认也不授予当前上传许可。
4. **最终性能与费用验收**：在获准环境实测整盘分析、分支分析耗时与试下体验，并结合真实用量、计价、并发在途及滞后计费验证月度预算控制；尚无实际延迟、硬件成本或可轻易守住预算的证据。
5. **最终教学验收**：使用核验局面与真人新手试用，检查精选 1–3 个局面的可理解性、教学推荐合理性、证据可靠性及约 10–15 分钟的真实教学体验；评估无合适局面的情形。练习来源、核验办法及掌握标准确定后，结合后续实际对局观察迁移。浏览器流程通过不能替代此项，也不能证明所有棋理正确。

# Pi 适配与模型分工

本文件是本项目的 Pi 适配层，不是 Matt 原版技能。
上游技能保存在 `.pi/skills/<name>/`，保留原始内容。

## 固定配置与动态任务

- 主会话：openai-codex/gpt-6-astra，high。
- 所有子代理（implementer、reviewer、general-purpose、Explore、Plan）：统一使用 `openai-codex/gpt-6.1-sol`，`thinking: max`。
- 主会话启动默认值仍由 `.pi/settings.json` 控制，本次只调整子代理；子代理参数固定在 `.pi/agents/*.md`，不依赖口头重复。
- 新建和续接子代理均遵循上述模型配置；已运行的推理不会因文件修改而热切换，需在安全检查点保存进度后使用新配置接续。
- agent 文件只定义角色底线。主代理必须为每次调用编写具体 prompt：
  任务目标、规格/任务路径、已确认决策、测试边界、修改范围、依赖与验收标准。
- 不用 general-purpose 绕过 implementer/reviewer 的固定配置。
- 此处“主代理负责调度”仅适用于主会话；子代理不继承调度职责。

## 技能调用

- Pi 用户命令为 `/skill:<name>`。
- 上游文字中的 `/to-spec` 等是技能名，在 Pi 中使用 `/skill:to-spec`。
- 上游要求 `/clear` 时，在 Pi 使用 `/new`；先按需生成 handoff，避免丢失未落盘的决定。
- 上游要求“Call the Skill tool”时，使用 read 读取本项目
  `.pi/skills/<name>/SKILL.md` 并执行；不存在名为 Skill 的工具时不要尝试调用。
- 读取相对引用文件时以实际技能目录为基准。
- 正常项目资源加载时，项目副本优先于同名全局技能；本项目工作流以此项目副本为准。
- 技能内的 agents/openai.yaml 是 Codex 元数据，不是 Pi 子代理配置。
- 用户主动调用类技能保持主动调用；安装不代表立即执行所有技能。
- wizard 和 diagnosing-bugs 附带的 Bash 模板只供明确任务使用，不在安装或加载时运行。
  交互式脚本需在人类可操作的终端运行；外部配置、密钥写入和远程操作先征得同意。
- 后续运行 setup 时继续维护现有 AGENTS.md，不另外创建一份竞争的 CLAUDE.md。

## 规划与实施

1. 主代理与用户澄清需求，必要时使用 grill-with-docs。
2. 大功能使用 to-spec / to-tickets；小修小改不强制生成整套文档。
3. 主代理确认验收标准和 TDD 测试边界，再委派 implementer。
4. 当用户运行 implement 时，主代理组织流程，把实际编码委派给 implementer；
   子代理完成后由主代理组织审查，避免实现代理自行审查自己。
5. 主代理检查实际修改与测试证据，而不只转述子代理的“完成”声明。

## 审查

- 主代理读取 code-review 原版技能，确定 Spec 和 Standards 两个维度。
- 为两个维度分别调用 reviewer；必要时并行，每次给出完整的维度说明、
  原版技能要求的基线、规范/规格来源以及准确的 diff 命令。
- reviewer 不预加载 code-review 编排技能，不启动嵌套代理。
- 原版三点 diff 只适用于已提交的变更。对于未提交工作，主代理明确提供
  工作区、暂存区、未跟踪文件的审查范围，不能用空的提交间 diff 代替。
- 没有 Git 仓库时可以审查明确列出的文件，但必须说明缺少历史基线。
- 按两条审查轴报告；修复由 implementer 完成，之后运行针对性的验证。

## Git、并行与完成边界

- 此配置不初始化 Git，不创建首次提交。需要 worktree 时先检查是否为 Git 仓库、
  是否有提交，以及隔离是否启用；不满足就报告前提，不静默并行写同一工作区。
- worktree 看不到主工作区未提交或未跟踪的文件。规格、任务和必要代码必须在
  派发前变得可访问；提交前取得授权，不擅自把用户其他修改一并提交。
- 非隔离实现默认一次一个。并行实施须基于清楚的依赖关系和独立 worktree。
- 插件保留变更分支并清理临时 worktree，不会自动整合到主分支。
  主代理负责验证分支和安排整合；需要委派合并时仍使用 implementer。
- 依赖任务必须基于已整合的最新基线启动，不能只等待另一代理结束。
- 不给未提交 diff 的审查创建新 worktree。
- 整合后再次验证；完成证据与任务状态由主代理统一收尾。
- 不推送、发布或操作远程任务系统，除非用户明确要求。
- 明确要求 workflow/多代理编排时才使用 SubagentWorkflow；不要因安装了
  implement-spec 就自动启动大规模流程。用户调用 implement-spec 时仍须检查 Git 前提。
